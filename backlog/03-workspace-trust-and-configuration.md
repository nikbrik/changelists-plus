# 03. Workspace Trust и безопасная конфигурация

## Цель

Исключить автоматический запуск произвольного executable из настроек репозитория и формально описать поведение расширения в Restricted Mode.

## Анализ

Настройка `changelistsPlus.gitPath` сейчас имеет стандартный scope и может задаваться workspace. Значение читается при активации, после чего сразу выполняются Git-команды. Без декларации capabilities VS Code по умолчанию отключает расширение в Restricted Mode, а изменяющие команды дополнительно проверяют `workspace.isTrusted`; однако это не защищает уже доверенный workspace от закомывания вредоносной настройки executable.

## Зависимости

- Эпик 01.
- Использует типизированные ошибки эпика 02, но может разрабатываться параллельно после фиксации контрактов.

## План реализации

1. Явно объявить `capabilities.untrustedWorkspaces.supported: false` с локализованным объяснением.
2. Сделать `gitPath` user/machine-only либо читать только `globalValue`; workspace/folder/language overrides игнорировать.
3. При обнаружении запрещённого override показывать безопасное предупреждение без запуска указанного файла.
4. До инициализации `GitService` проверять Workspace Trust и существование разрешённого executable.
5. При выдаче trust заново инициализировать сервис и watchers без перезапуска окна.
6. Добавить manifest и integration-тесты для user value, workspace override и Restricted Mode.
7. Документировать threat model настройки и безопасный способ указать нестандартный Git.

## Критерии качества и приёмки

- Репозиторий не может заставить расширение запустить путь из workspace/folder settings.
- В Restricted Mode расширение не запускает Git, не создаёт watchers и не изменяет storage.
- После явной выдачи trust функции становятся доступны без двойной регистрации listeners/commands.
- Нестандартный Git можно настроить на уровне пользователя документированным способом.
- Contract-тест автоматически падает при удалении декларации Workspace Trust или ослаблении scope.
- В VSIX отсутствуют иные настройки, позволяющие передать executable, arguments или environment из workspace.
