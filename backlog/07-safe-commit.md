# 07. Безопасный commit одного changelist

## Цель

Вернуть самостоятельный commit только после доказательства сохранности worktree и ранее staged-изменений при успехе, отказе и прерывании.

## Анализ

Текущая идея временного `GIT_INDEX_FILE` правильная: выбранный patch коммитится независимо от реального index. Риск возникает после обновления `HEAD`, когда реальный index сбрасывается и staged snapshot восстанавливается несколькими командами. Нужна транзакционная публикация результата, concurrency guard и journal.

Commit hooks являются ожидаемым выполнением кода доверенного репозитория. UI должен явно следовать Workspace Trust, поддерживать timeout и корректно показывать отказ hook без раскрытия секретов.

## Зависимости

- Эпики 01–06.

## План реализации

1. Формализовать инварианты commit для worktree, выбранного patch, чужого staged patch и `HEAD`.
2. Подготовить commit в изолированном temporary index и проверить получившийся tree до обновления ref.
3. Создать durable journal со staged/worktree snapshots.
4. Под контролем coordinator проверить неизменность исходных `HEAD` и index.
5. Опубликовать commit и сформировать новый index во временном файле, включив только допустимый восстановленный staged patch.
6. Атомарно заменить реальный index после повторной проверки fingerprint; не использовать окно `reset → apply` на реальном index.
7. При hook failure, timeout или ref race оставить исходные состояния нетронутыми либо запустить доказуемое recovery.
8. Вернуть команду/UI только после полного набора integration и crash-тестов.

## Критерии качества и приёмки

- Успешный commit содержит ровно выбранные hunks, остальные worktree changes остаются побайтово прежними.
- Ранее staged hunks, не вошедшие в commit, остаются staged относительно нового `HEAD` либо операция заранее отказывается как неоднозначная.
- Реальный index не находится в промежуточном сброшенном состоянии между отдельными Git-командами.
- Hook failure/timeout не меняет `HEAD`, index или worktree.
- Concurrent ref/index change приводит к безопасному отказу, а не к overwrite.
- Crash в любой fault-injection точке полностью восстанавливается через эпик 06.
- Перед подтверждением UI показывает точный diff создаваемого commit.
