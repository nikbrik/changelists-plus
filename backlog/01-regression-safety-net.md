# 01. Защита от регрессий и тестовый контракт

## Статус

Реализован. Production-код и пользовательское поведение не изменялись.

## Цель

До изменения production-кода зафиксировать наблюдаемое безопасное поведение расширения и создать тестовую инфраструктуру для аварийных, конкурентных и платформенных сценариев.

## Анализ

В проекте уже есть 85 интеграционных и модульных тестов, хорошо покрывающих parser, matching, store, stage, commit и discard. Основной пробел — проверки нештатного завершения между Git-командами, параллельного изменения `HEAD`/index, частичного результата многофайловой операции, зависших процессов и границы Workspace Trust. Текущий тестовый helper также наследует пользовательскую настройку `commit.gpgSign`, из-за чего результат зависит от машины.

Эпик должен добавлять только тесты, fixtures и test-only hooks. Изменение пользовательского поведения здесь запрещено. Известные дефекты оформляются отдельными acceptance-сценариями с явной пометкой ожидаемого нарушения; основная ветка при этом остаётся зелёной.

## Зависимости

Нет. Это первый обязательный эпик и блокер для всех последующих.

## План реализации

1. Разделить test helpers для файловой системы, временного Git-репозитория и запуска Git.
2. Изолировать тестовые репозитории от пользовательских настроек Git: задать локальные identity и `commit.gpgSign=false` только внутри fixture.
3. Добавить управляемый fake Git process: exit code, stdout/stderr, задержка, зависание и принудительное завершение.
4. Добавить снимок инвариантов репозитория: `HEAD`, байты worktree, содержимое index и staged patch до/после операции.
5. Добавить fault-injection точки между шагами commit/discard без изменения production-алгоритма.
6. Зафиксировать characterization-тестами существующие гарантии: успешный stage/commit, отказ hook, merge/rebase/conflict guards, CRLF, бинарные и необычно названные файлы.
7. Добавить сценарии известных рисков: изменение index/HEAD конкурентом, сбой в середине многофайлового discard, timeout, symlink и восстановление после прерывания.
8. Добавить статические contract-тесты для manifest: команды, настройки, Workspace Trust и состав VSIX.
9. Разнести быстрые unit-тесты и Git integration-тесты по отдельным npm scripts, сохранив общий `npm test`.

## Критерии качества и приёмки

- `npm test` проходит на чистой машине независимо от глобального GPG signing.
- Все существующие 85 тестов сохранены или заменены тестами с не меньшей проверяемой областью.
- Для каждой будущей защитной меры из эпиков 02–08 существует тест, который способен упасть при её удалении.
- Тесты проверяют байтовую сохранность worktree и фактический staged patch, а не только коды возврата.
- Нештатные сценарии детерминированы и не используют timing-only ожидания.
- Test fixtures удаляются после успеха и ошибки; тесты не меняют пользовательские Git config, index или репозитории.
- В основной ветке нет постоянно падающих тестов; известные нарушения перечислены как явно именованные pending/known-risk cases с ссылкой на целевой эпик.
- В CI доступны отдельные результаты unit и integration suites, общий прогон завершается ненулевым кодом при любой неожиданной регрессии.

## Реализованный контракт

- Общий runner поддерживает `unit`, `integration` и `contract` suites; `npm test` по-прежнему запускает их вместе.
- Git/FS fixtures вынесены отдельно, временные пути регистрируются в harness и удаляются после каждого успешного или упавшего теста.
- Каждый тестовый репозиторий получает локальные identity, `commit.gpgSign=false` и собственный `core.hooksPath`; пользовательские Git-настройки не изменяются.
- Управляемый fake Git моделирует exit code, stdout/stderr, spawn error и детерминированное зависание через явно освобождаемый gate.
- Snapshot репозитория сравнивает `HEAD`, реальные index entries, бинарный staged patch, байты worktree и цели симлинков.
- Fault injection до записи временного index и падающий pre-commit hook проверяют полную сохранность snapshot.
- Существующие проверки покрывают успешные stage/commit/discard, merge/conflicts, CRLF, binary, untracked, symlink и необычные имена; добавлена отдельная проверка rebase guard.
- Известные риски эпиков 02–08 зарегистрированы как явно именованные `PENDING KNOWN RISK` и не маскируют неожиданные падения.
- Manifest contract фиксирует набор критичных destructive/staging commands, security-sensitive `gitPath` и наличие VSIX verifier.
- `verify:vsix` побайтово сравнивает находящиеся в VSIX `package.json` и compiled JavaScript с checkout и запрещает попадание test-кода в архив.
- GitHub Actions публикует отдельные результаты `unit`, `integration` и `contract`; каждый job завершается ненулевым кодом при регрессии.

## Команды приёмки

```sh
npm test
npm run test:unit
npm run test:integration
npm run test:contract
npm run verify:vsix -- path/to/changelists-plus.vsix
```
