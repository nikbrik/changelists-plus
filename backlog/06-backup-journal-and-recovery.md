# 06. Журнал операций, backup patch и восстановление

## Цель

Гарантировать восстановление пользовательских изменений после падения extension host, VS Code или машины во время изменяющей операции.

## Анализ

`finally` очищает временные файлы только при штатном завершении процесса. Падение после изменения `HEAD` или реального index оставляет операцию без контекста восстановления. Для безопасных commit/discard нужен write-ahead journal: сначала durable snapshot и намерение, затем изменения, затем атомарная отметка завершения.

Backup не должен содержать секреты вне локальной машины или попадать в репозиторий. Поскольку patch содержит исходный код и потенциально чувствительные данные, хранение ограничивается VS Code global/workspace storage с приватными правами и понятной политикой удаления.

## Зависимости

- Эпики 01, 02 и 05.

## План реализации

1. Определить версионированный формат journal: repo identity, operation id/type, исходные HEAD/index fingerprints, worktree/staged patches и этап.
2. Перед изменением состояния атомарно записывать journal через temp file + fsync + rename.
3. Обновлять этапы операции монотонно и idempotently.
4. При активации находить незавершённые операции и предлагать Preview, Restore или Keep Current State.
5. Проверять fingerprint перед автоматическим restore; при расхождении только показывать инструкции/patch.
6. Хранить backups вне worktree, запретить telemetry/logging содержимого и установить приватные permissions.
7. Добавить retention/ручную очистку только для завершённых записей; незавершённые не удалять по TTL без решения пользователя.
8. Тестировать kill/restart после каждого journal state и повторный recovery.

## Критерии качества и приёмки

- Перед первой мутацией существует durable snapshot, достаточный для восстановления worktree и index.
- Принудительное завершение после любого шага обнаруживается при следующем запуске.
- Recovery можно безопасно повторить; второй запуск не удваивает patch и не ухудшает состояние.
- При несовпадении fingerprint расширение не выполняет автоматическую перезапись.
- Backup-файлы не входят в Git status/VSIX, создаются с доступом только текущему пользователю и не логируются.
- Интеграционные crash-тесты проходят для каждого изменяющего этапа.
