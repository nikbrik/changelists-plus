# 02. Безопасная граница запуска Git-процессов

## Цель

Сделать каждый запуск Git ограниченным по времени и памяти, корректно завершаемым и диагностируемым без утечки содержимого изменений.

## Анализ

`GitService.runRaw` использует `spawn` без shell, что защищает от обычной shell-инъекции. Однако timeout отсутствует, stderr не ограничен, а stdout допускает до 256 МБ. Зависший Git, hook или credential helper может навсегда оставить Promise незавершённым; большой вывод способен исчерпать память extension host. После превышения stdout-порога процесс убивается, но причина не представлена отдельным типом ошибки.

## Зависимости

- Эпик 01.

## План реализации

1. Ввести типизированные лимиты выполнения: deadline, максимальные stdout/stderr и grace period завершения.
2. Добавить единый результат `timed_out`/`output_limit`/`spawn_failed` вместо неразличимого `code=-1`.
3. По timeout сначала отправлять мягкое завершение, затем принудительное после grace period; гарантированно снимать timers/listeners.
4. Ограничивать оба потока во время чтения без накопления данных сверх лимита.
5. Использовать короткий timeout для read-only команд и отдельный увеличенный timeout для commit/hooks.
6. Не включать patch, содержимое файлов, переменные окружения или секреты в пользовательскую диагностику.
7. Протянуть отмену при деактивации расширения и закрытии workspace.
8. Добавить тесты fake process для успеха, timeout, переполнения каждого потока, spawn error и гонки close/error.

## Критерии качества и приёмки

- Ни один дочерний процесс расширения не может работать бесконечно без контролируемого cancellation token.
- При превышении лимита память не растёт пропорционально дальнейшему выводу процесса.
- Timeout и output limit имеют разные локализованные сообщения и технические коды.
- Аргументы запуска по-прежнему передаются массивом при `shell: false`.
- Все fault-injection тесты эпика 01 проходят без зависаний и открытых handles.
- Диы не содержат patch/file contents или полного environment.
- Обычные Git-операции и hooks укладываются в документированные настраиваемые пределы.
